# ApplyKit 2.2.0 验收

日期：2026-09-12。环境：Windows x64、Go 1.26.5、Windows PowerShell 5.1、Windows.Data.Pdf、Codex 内置浏览器。

## 自动检查

- Go 核心测试（54 项）：图片编码/限制、PDF、裁剪、偏好设置兼容、可调边距、预览归属、示例会话认证。
- `go vet ./...`。
- 三个前端模块语法检查与 3 项 Node 几何回归测试。
- 原生 Windows 自检：图标与版本资源、本地服务和内嵌资源、PDF 预览与可调边距、200 KB 图片裁剪旋转翻转、逐页 PDF 自动裁剪及空白页保护、手动裁剪及页码选择、图片合并与扫描 PDF 压缩、非法大小拒绝、原始样本字节保持不变。

原生测试记录见 [windows-acceptance.json](windows-acceptance.json)。不通过哈希清单验收文件。

## 实际界面检查

- 从文件选择器加入合成 PDF，生成真实预览，并执行三页自动裁剪导出。
- 调整 5 mm 边距，预览与导出范围同步变化。
- 通过内置示例加载图片，在编辑器旋转 90°、水平翻转、选用 3:4 比例后保存；侧栏显示已编辑，真实导出至 200 KB 上限以内。
- 首次启动输出目录和默认自动裁剪正确；底部“处理完成后打开文件夹”可点击。
- 检查 1536×1024、1366×768、1024×768 布局、队列溢出与底部操作区；检查深色主题。
- 浏览器控制台未发现 error / warn。

## 验证边界

Windows.Data.Pdf 和最终 EXE 的本地服务已实际运行；界面使用内置浏览器验收。系统 Edge/Chrome 独立应用窗口的标题栏、所有 Windows 显示缩放比例及文件夹选择器没有逐一进行人工验收。内置浏览器文件选择器在后续操作出现连接超时，因此图片界面流程使用内置合成示例完成；该限制不影响本地引擎测试。

不把跨平台单元测试中的模拟 PDF 渲染器当作 Windows 原生验证。未经测试的超大 PDF、加密 PDF 组合、损坏输入和特殊受管 Windows 环境仍可能有边界情况。扫描 PDF 重建不保留文本层与签名。
